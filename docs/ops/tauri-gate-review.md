# Tauri 桌面壳 · 门口评审记录（方案 D4，2026-11-08）

> 评审性质：文档性判定（无代码变更）。依据：[方案 §16/§18 D4](../../research/main-agent-proposal.md) 与 M1/M2 实施数据。

## 结论

**不做 Tauri 桌面壳，维持「浏览器 tab 直连本地 FastAPI」形态。** 退化路径留档：如未来出现独立窗口需求，先走 pywebview 轻窗（I-41，零构建链），Tauri 仅在 pywebview 不满足时重开评审。

## 依据

1. **使用数据不足**：M1 面板 0.0.3 起在线、0.0.7 全页点亮不足一日，无「面板稳定使用 ≥4 周」的实证——门口评审（方案 D4「以 M1 使用数据判定」）在数据面上只能得出「不足以支持引入」。
2. **方案自评边际价值存疑**：候选 C（Tauri 壳+sidecar）评审 value 7/10 为三候选最低（方案前置说明）；其收益（独立窗口/系统托盘）与成本（Rust 构建链+sidecar 打包+升级通道维护）比不成立。
3. **结构保证已覆盖**：浏览器 tab 永为完整后备（方案 §8 无条件结构保证——SSE/htmx 双通道下 tab 即完整功能面）；面板绑定 127.0.0.1+TrustedHost，无对外暴露诉求，桌面壳的安全收益为零。

## 触发再评条件

同时满足以下两条时重开本评审（届时按方案 D4 补充实测数据）：

1. 面板稳定日常使用 ≥4 周（decisions.jsonl 连续画像可证）；
2. 出现真实的多窗口/离浏览器工作流需求（如盯盘事件浮层、复盘双窗对照），且 pywebview 轻窗先试验证仍不满足。
